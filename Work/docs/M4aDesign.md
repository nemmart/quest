## 1. Address space — RULINGS

- **Base 0x78000000.** Ring bits stay 7, bit 31 (the @ indirection
  flag) clear, `Machine::copy_segment` round-trips it unchanged
  (0x08000000 | 0x70000000), page number 0x1E0000 fits `blocks[]` /
  `permissions[]`. Sparse page map: the block table costs one Block;
  nothing below or above is disturbed.
- **Ring 6 REJECTED.** `Machine::eagle_x_resolve_indirect` applies
  `copy_segment(pc, ac[2|3]+disp)` on the short X-form (the common
  `[ac3+d]`) — a 0x6xxxxxxx base would silently re-ring to 7. Long
  L-forms do not re-ring. Not worth an emulator adjustment.
- **Nothing maps at or above 0x78000000 today.** Ring-7 facts from
  c_src/log (QUEST client): unshared image pages 0–5 (stack base
  0x70000E87), shared image 0x70017C00–0x7017FFFF, and the three
  ?SPAGE windows — SHARED_DATA_FILE at **0x70180000** (126 pages, to
  ~0x7019F800), WORLD_DATA_FILE at 0x70017C00 (1033 pages),
  CASTLE_DATA_FILE at 0x7012AC00 (63 pages). ?SSHPT extends the
  shared partition at startup (this is why 0x70180000 is legal). ?MEMI
  is dead in the live configuration. QUEST_SERVER lays out
  differently (SD at 0x7003F400; windows at 0x70180000, 0x70152400)
  — same Memory class, irrelevant to the client.
- **Static layout, mapped at launch.** NOT lazily mapped (ruling):
  the address book fixes every routine's area; the clone maps exactly
  the book's page count at launch, RW, no exec. A stray access outside
  the laid-out region faults loudly instead of minting a page.
- **Census = confirmation, not search** (ride-along step): an
  ever-mapped bitmap in `Memory::map_page` + a `pagemap` trace line
  per map/unmap/?SSHPT/?MEM(I) + shutdown dump, run under the battery;
  plus a static sweep of quest.dis/quest.mem for absolute addresses
  ≥ 0x78000000. Expected result: empty.

## 2. Scope facts (from the disassembly, verified this session)

- **74 named game routines**, every one reached only by
  `LCALL [abs],N`, arg count on the instruction, every target a
  symbol (0 unnamed LCALL targets in the game range).
- **49 unnamed WSAVS entries** = nested procedures, reached by
  `XCALL 0,N,[pc+rel]` (63 sites). NOT via the saved-wfp chain: the
  **static link is passed in a register** — call site `WMOV 3,1`
  (child of the caller) or `XWLDA 1,[ac3+0x7FFA]` (sibling: reload own
  saved link from the WSAVS ac1 slot) or `WMOV 2,1`; child uses ac1 /
  `WMOV 1,2` and addresses parent locals `[ac2+d]`. All 63 sites
  conform. Consequence: nested routines and their parents can migrate
  INDEPENDENTLY — the link is just a base value that round-trips
  through the WSAVS image. Sequencing is free.
- **Entry variants in game code: WSAVS (124) and WSAVR (2:
  LOCK_FILE, UNLOCK_FILE).** No WSSVS/WSSVR, no XPSHJ callee frames.
  Both push the same five-wide image; one hijack code path.
- **Dynamic stack use** (per-routine census; WSTB is store-byte, NOT
  a stack op — excluded): WMSP/STASP/LDASP (real dynamic locals) in
  13 routines: DIED, DISPLAY_MAGIC, DISPLAY_CAVE, DISPLAY_SCREEN,
  DISPLAY_INVENTORY, GET_QUEST, INIT_OBJ_TBL, OBSERVE, and nested
  ones under HELP, LIST_PLAYERS, OP_HELP(3), STORE. WPSH/WPOP
  balanced pushes in ~15 more.
- **WAVE ONE = PURE ONLY (ruling, conservative):** no WMSP/STASP/
  LDASP AND no WPSH/WPOP. ~74 of 126 entries qualify. The rest appear
  in the book COMMENTED OUT (visible, flippable later).
- Mixed arg counts: REFRESH_SCREEN (0/1), RETURN_MESSAGE (3/6). Tool
  flags them; sizing uses the max.

## 3. The address book

Generated by `tools/build_address_book.py` over Disassembled/quest.dis
+ quest.symbols. Deliverable is `quest.addrbook` (input to the run,
`QUEST_ADDRESS_BOOK=<file>`), plus a side report (call sites per
routine, flags, exclusions and why).

Per routine: entry pc, name (nested: `PARENT.n@<pc>` — enclosing
symbol by address), variant, WSAVS frame size, **max argc over all
call sites**, call-site count, dyn/push flags, and the layout — **a
verbatim frame image, formatted exactly like the master's stack
frame** (ruling):

```
alloc_base                    (16-word aligned)
  args:  max_argc wides       arg N at wfp-10-2N (pointer wides)
  LCALL frame word (wide)     (psr<<16)|argc at wfp-10
  restore image (5 wides):    ac0 @ wfp-8, ac1 @ wfp-6 (= static
                              link for nested), ac2 @ wfp-4,
                              prev wfp @ wfp-2, ac3|carry @ wfp+0
  ← wfp (ac3 points here)
  WSAVS space: frame_size words
next alloc_base
```

(Offsets from EagleStack WSAVS/WRTN + Machine::wide_push: a wide
occupies [wsp..wsp+1] after `wsp+=2`.) Sizing = max_argc*2 + 2 + 10 +
frame_size words, rounded. Bases assigned sequentially from
0x78000000; header records total page count. One line per routine,
hand-editable and diffable:

```
# entry     name              alloc_base  wfp_base   argc frame variant flags
7016E103    INIT_SCREEN       78000000    7800000C   1    0x05  WSAVS   -
#7016603D   DIED              ...                                        dyn
```

Absent/commented = stays stacked. **The book IS the opt-in table**:
routine-by-routine migration under lockstep, bisection by halving the
book, stragglers may stay stacked indefinitely.

## 4. The hijack (clone only; game code untouched)

**Two instructions hijacked: WSAVS/WSAVR and WRTN.** Both keyed off
the book (WSAVS by pc; WRTN by "is wfp an area address").

- **Hijacked WSAVS/WSAVR** (pc in book):
  1. Read the LCALL frame word at [wsp] for the ACTUAL argc (RTBridge
     already reads it). Copy the args (argc wides) + the frame word
     from the real stack into the area at the same offsets. Mirror is
     sized for max argc; unused slots keep prior content.
  2. Push the five restore wides (ac0, ac1, ac2, wfp, ac3|carry)
     **into the area**, not the stack. The real stack is untouched:
     it keeps only the args + frame word the caller pushed. (Earlier
     "WSAVS 50 executes as WSAVS 0" sketch superseded — no restore
     image on the stack at all.)
  3. wfp = ac3 = area wfp. LDAFP 3 refreshes it stock after calls.
     ovk per variant as today; zero_claim on the WSAVS space per
     ruling 8.
  Not in book: exact current behavior.
- **WRTN: stock + one wsp fixup, gated by "wfp is an area address"
  (range test on the register, NOT a pc map — ruling).** Traced
  against the verbatim layout, stock WRTN produces every VALUE
  correctly from the area image: `wsp = wfp` lands in the area, then
  ac3|carry, prev wfp, ac2/ac1/ac0 (patches included), and the frame
  word all pop from the area at the stack offsets. The only wrong
  output is the final wsp (area wfp-10-2*argc). Fixup: after the
  stock sequence, `wsp = real_wsp_at_WSAVS - 2 - 2*argc` — discard
  the frame word + args the caller pushed on the real stack; the live
  record already holds real_wsp_at_WSAVS. Everything else stock. The
  same range test is the discriminator for anything that migrates
  later (WMSP locals, nested frames): "is this an area address," not
  "which pc am I at." The book is consulted BY PC only at WSAVS,
  the one moment a choice is made.
- **Slot-patch return convention is REAL in game code** (user's
  catch): 18 routines store return values into the saved-ac0 slot
  (`XNSTA 0,[ac3+0x7FF9]` = low word of ac0 @ wfp-7, or `XWSTA
  0,[ac3+0x7FF8]` full wide) — OWNS, RANDOM, DIST,
  DISTANCE_TO_PLAYER, DEFEND, LOOK, BOAT, SEIGE, MOVE_PLAYER,
  MOVE_IN_CAVE, and nested procedures under AUTO_MOVE, BARGAIN, BOAT,
  LIST_PLAYERS, LOGON. Same convention as ?UDIV32. Satisfied by
  construction: the area image is the restore source.
- LDAFP, XPEF/LPEF, LCALL, the caller side: unmodified. "Previous
  wfp" is a value the image round-trips, so the caller's base (stack
  or area) is restored without knowing anything changed. Mixed mode
  composes with no extra machinery.
- Static links (nested procedures) unchanged: register values that
  live in the saved-ac1 slot of the area image.
- The area frame and the master's stack frame are THE SAME BYTES at
  different addresses — a future memory compare is a straight T().
- Boot-gate note: a migrated routine never trips the wsp==wsl
  overflow; only I.INIT relies on it and that is runtime, not game.
- Per-routine live flag set/cleared at hijacked WSAVS/WRTN = the
  dynamic re-entrancy tripwire (abort_world on violation).

## 5. Checker Generation 4 — RULINGS

**Premise (user):** the clone's stack may look COMPLETELY different
from the master's — wave one only hijacks WSAVS, but the checker is
built for the general case from day one. The invariant is not "clone
stack = master stack minus some frames"; it is: **every clone address
that the master would hold as a stack address must be translatable
to the master's value.** All of this work lives in the clone.

- **Shadow master-wsp SIMULATION.** The clone runs the master's stack
  arithmetic in parallel, independent of what its own stack does:
  every instruction that moves wsp on the master (WSAVS/WSAVR by
  full size, WRTN, WPSH/WPOP, WMSP, XPEF/LPEF, LCALL, the condition
  system's cuts on unwind — native I.GOTO already owns the wsp reset)
  updates shadow_wsp by the MASTER's amount. This is Plan.md's
  "de-stackify the storage, keep the accounting", made the actual
  mechanism.
- **Live allocation table.** Every clone allocation, wherever it
  physically lands (area, real stack, anything), records
  `(clone_addr, shadow_master_addr, size)` on hijacked WSAVS (one
  record per live area frame: alloc_base → the master's frame base at
  the shadow wsp) and drops it on hijacked WRTN / unwind. Translation `T(clone_value)`: if the
  value falls in a live record → `master_addr + (value − clone_addr)`;
  else identity.
- **Register rule at every pair, all four ACs + carry:** pass if
  `clone == master` OR `T(clone) == master`. wsp: pass if
  `shadow_wsp == master wsp` — the strongest self-check: any missed
  accounting fails every subsequent pair.
- **Mediation (syscall packets, shared writes, L2 crossing entry
  state):** contents compared STRICTLY; pointer-shaped fields
  translated through T before comparing (field-by-field where the
  packet layout is known — the mediator already reads packets by
  field name — word-by-word range test for opaque regions). Escaped
  local pointers (`XPEF [ac3+n]`), static links, buffer addresses in
  ?READ/?WRITE, ac2 packet pointers: all covered by the same T. The
  clone executes its own syscall locally, so result copies already
  land at the clone's addresses.
- pc streams and instruction counts stay STRICT and IDENTICAL (code
  unchanged) — the big win over M3's native spans. All L1 fabric and
  L2 crossings pairs unchanged.
- Recognizing addresses: range test against the book / live records
  suffices — no legitimate game integer lands in 0x78xxxxxx.
- CheckerHistory.md gets a Generation 4 entry from this section.

## 9. Amendments after Project 13 batch 2 (Aug 15 2026, ruled)

- **RULING — address-book base moves to 0x74000000.** Project 13
  found (boundary 2) that with base 0x78000000 an AREA BYTE POINTER
  (`0x78… << 1 = 0xF0…`) is prefix-identical to a REAL-STACK @-WORD
  (`0x80000000 | 0x70… = 0xF0…`); §8's ordered-guess T_any then
  mistranslates area byte pointers (LOGON's ac2 at ?WRITE_SCREEN,
  GET_INPUT's ?READ packet field). Reordering (their R1) is UNSOUND:
  a real @-word's `>>1` can land inside a live area (P12's own
  0xF0001152 >> 1 = 0x78000A29 ∈ BACKPACK's area). Root cause: bit 27
  set in the base puts the shifted form on the @-flag band. With base
  **0x74000000** every form is disjoint by prefix:
  real word 0x70 / area word 0x74; real byte 0xE0 / area byte 0xE8;
  real @ 0xF0 / area @ 0xF4. Ring bits 7, bit 31 clear,
  `copy_segment` (mask 0x0FFFFFFF) and `set_byte_segment` (mask
  0x1FFFFFFF) preserve the distinguishing bit; census: nothing mapped
  anywhere near. Book FORMAT unchanged; header base + regeneration.
- **DESIGN INVARIANT (now stated):** the pointer forms of area
  addresses must be separable from every real-stack form BY PREFIX;
  that is a constraint on the base. **T_any becomes prefix DISPATCH,
  not ordered guessing**: decode the form from the top bits, translate
  the underlying word (area record or real-stack shift), re-encode the
  same form. Deterministic.
- Regression targets: the two saved divergence signatures
  (Project13/evidence/div_b2_*.txt) must pair.
- **Rename (housekeeping):** "hijack" → "redirect" (WSAVS redirect /
  area redirect) in prose, trace type `hijack` → `redirect`, and code
  identifiers as the touched files allow. Design doc prose is not
  retro-edited except this note.
- Ratified from Project 13's Stage 0: `nocall` flag + exclusion;
  `gcalls` trace (both roles, pure observer at the LCALL/XCALL site)
  with the standing invariant gcalls == redirect-WSAVS count per live
  routine; the `play` driver grown in place. Batch 1 (READ_IN, OWNS,
  FIND_OBJECT, RANDOM, DIST, DISTANCE_TO_PLAYER) LIVE-VALIDATED at 0
  div under the full battery.
