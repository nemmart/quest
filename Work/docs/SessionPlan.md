# Session Plan — Step 1: 100% C++ Runtime

*Created: August 2026. Detail plan for Step 1 of Plan.md: get Quest
running with no emulated PL/1 runtime. Expected to span this session
and likely the next.*

## Goal

Every PL/1 runtime routine the game reaches is served by native C++
via NativeRegistry, validated under the lockstep harness. Afterward,
the emulated stack is touched only by compiled game code, clearing the
way for de-stackification (Plan.md Step 2).

## Tasks

### A — RT entry stubs + coverage + entry sync (agreed design)

1. **Log-and-continue stubs**: a native C++ entry point for every
   runtime symbol (~90, including all condition-system entries),
   generated by macro, registered in the **clone only** (master stays
   pure emulation; non-lockstep runs stay pure). Each stub logs an
   `rtcalls` trace line (instance, routine, return addr) and returns
   its entry address so emulation proceeds normally. This exercises
   the real registration→lookup→dispatch→return path at every site,
   thousands of times per session, before any real translation lands.
2. **LJSR/XJSR dispatch**: extend registry lookup to LJSR/XJSR in
   EagleGeneral (today only LCALL/XCALL in EagleStack consult it) —
   required for the condition-system entries.
3. **PC-bitmap coverage**: cheap bit-per-word over the RT range in the
   instruction loop for QUEST machines, dumped at shutdown. Safety
   net: covered addresses not attributable to a logged entry's routine
   = hidden live code / unhooked entry paths. Also finds hidden live
   code in `mem`-classified ranges.
4. **RT-entry sync points (permanent architecture)**: master and clone
   batches break when pc arrives at an RT entry; the existing pair
   checker verifies both engines at the same entry with the same
   argument state. The sync identity is the *RT entry address as a
   logical event*, not "same pc by emulation": today both sides arrive
   by emulating; after a routine is translated, the clone arrives by
   native dispatch on the same address — same architectural point
   (LCALL setup complete), so entry-argument comparison stays valid
   forever. Entry checks verify arguments; syscall rendezvous,
   shared-write checks, and the next entry verify effects. This
   tightens the syscall-only sync PortingPlan expected for translated
   stretches. Implied adjustments when translations land: pair keying
   on event address rather than ending pc, and instruction-count
   comparison relaxed across native spans.

Registration timing fix required: register_all currently runs in the
OSProcess constructor, before Launch assigns lockstep_role; move it to
launch().

Outputs: the reached-routine worklist (rtcalls log), hidden-live-code
list (bitmap vs attribution), dispatch-path confidence, and standing
argument checks at every runtime call.

## Queue instructions — RESOLVED (section retained for history)

Original hard stop (ENQH unimplemented, ENQT/DEQUE untrusted) resolved
Aug 2026: all three rewritten/implemented from the DG queue-management
chapter (QUEUE_INSTRUCTIONS.md), and the I.ALLOC/I.FREE* chunk was
subsequently translated and validated (I_ALLOC.md). The residual gap is
`QSEARCH`, now classified a **hard terminal** (never guessed at; both
engines throw identically if ever reached — TerminalDetach.md) and off
the critical path since the free-list paths are structurally dead
(M3Plan.md heap note). The lockstep-can't-catch-shared-wrongness lesson
lives on in METHOD.md §2.

Translation checklist per routine (method and rationale:
`docs/METHOD.md`; known gaps: `docs/UNIMPLEMENTED.md`):
0. Grep the routine + its callees for ENQH/ENQT/DEQUE/QSEARCH — if
   present, FLAG AND STOP (see HARD STOP section above).
0a-bis. **THE GREP IS NOT SUFFICIENT — also check for `XCT`.** ENQH and
   ENQT appear NOWHERE as mnemonics in the runtime: the free-list
   insert builds the opcode as an immediate (`NLDAI 0xC7E9/0xC7F9`) and
   executes it via `XCT` at 0x7017E9F6. `XCT` can execute any
   instruction, so the instruction set a routine actually uses is not
   statically knowable from mnemonics. `XCT` is itself unimplemented,
   and also appears in `I.GOTO` at 0x7017ECF4. Also check `WBR 2`-
   skipped holes for opcode-shaped constants (0x7017E86B = `WRTN`,
   0x7017E899 = `ISZTS`). Full catalogue: **docs/UNIMPLEMENTED.md**.
0b. **Verify flag side effects of EVERY body instruction from the
   emulator source** — including skip/compare/zeroing idioms that look
   boring. Example (O.ON session): the helper preamble's WSUB 1,1
   zeroes ac1 but ALSO clears carry, changing the carry bit stored in
   its saved ret wide — a one-bit residue error caught only by
   capture diff. Register-zeroing (WSUB x,x), compares, and skips can
   all touch flags; derive residue from the source, never from the
   apparent intent of the instruction.
0c. **Know which instruction owns each convention side effect.**
   LCALL pushes the shadow call-stack frame; for LJSR routines it is
   WSSVS/WSSVR that pushes it (caller-pattern detection in
   EagleStack). A native wrapper replicating "half" a convention must
   pop only what was actually pushed — assuming symmetry with the
   LCALL bridge caused an "Empty call stack" crash three calls later.
0d. **WBLM direction conventions** (recorded to save re-derivation):
   positive count = forward copy (src/dst increment), negative =
   backward (start addresses are the TOP, decrementing); after: ac1=0,
   ac2/ac3 = final src/dst. For overlapping moves, note which source
   words the copy does NOT overwrite — O.ON's allocate path depends on
   the abandoned low words surviving a backward shift (the old saved
   block IS the new chain node)..
- Grep the body for stores into the WSAVS-saved register slots
  (frame-relative offsets where ac0-2/ac3 were pushed): some routines
  return values by patching the saved slots so WRTN restores modified
  registers. RTBridge restores entry values by default; a slot-patcher
  needs explicit return-register overrides (bridge extension when
  first needed). The native-span pair check (ac0-3 + carry at the
  post-call point) catches any miss on the first call.
- Check for calls in the body. The constraint is precisely: a native
  wrapper must not re-enter EMULATION mid-routine. Whole subtrees can
  go native together (master's run-to-return ignores nested entries
  while pending; the clone's wrapper calls the inner rt:: functions as
  plain C++). E.g. ?UNSIGNED_TO_CHAR + rt::udiv32_3.
- Note argument indirection levels from the actual call sites, not
  just the body (fill_words lesson #1: an arg can be a pointer variable
  passed by reference — dest was one dereference deeper than the slot).
- **Replicate the dead-stack footprint** (fill_words lesson #2, caught
  by a store-visit divergence): the emulated body's WSAVS frame and
  local writes persist as stack residue after WRTN, and some code READS
  residue — ?WRITE_SCREEN loads its never-initialized locals [4..5]
  into ac0 for SYSCALL 0303 (7017E2F1: XWLDA 0,[ac3+0x4] with no prior
  write; the slot is only stored after the syscall). Every translation
  must call RTBridge::emulate_frame() (writes the exact WSAVS image —
  entry ac0-2, wfp, ac3|carry) and replicate the body's local writes
  via write_frame_word/wide so master and clone residue stay
  bit-identical.

### D — Condition system (the centerpiece)

Design carefully as one chunk. Transition-period architecture (agreed):

- Game code is still emulated while the runtime goes native, so the
  handler chain lives in the *emulated* stack frames. Native
  I.PROLOG/O.ON maintain that chain in emulated memory; native
  O?SIGNAL/I.GOTO walk emulated frames and transfer control to
  emulated handler code.
- The stack-walking doesn't disappear at this stage — it moves into
  our C++ where we control it. It fully dissolves only after
  de-stackification (Plan.md Step 2).
- Surface is small: 26 handlers, all catch-all, 4 simple categories;
  EOF never uses this path.

### E — Endgame

Startup/shutdown, tasking, and any stragglers coverage says the game
reaches. Success criterion: a full play session (login, character
creation, combat, castles, inventory, save, logout) with zero emulated
instructions executed in the RT address range — confirmed by the
coverage trace showing an empty set.

## Task Step-1 progress (Aug 2026): I.LOCK / I.UNLOCK translated

Sixth and seventh translations, and the first pieces of the heap
subtree (plan: docs/HeapSignalPlan.md, derivation: docs/I_ALLOC.md).

- `runtime/i_lock.{hpp,cpp}` — uncontended acquire/release only.
  Registered in `translation_table`.
- **Chosen because their live path contains no syscall**, so they land
  before `RTBridge::syscall` exists. Every other part of I.ALLOC needs
  the heap-extend syscalls.
- Lock layout decoded: `[lock+0..1]` owner wide zeroed by the acquirer;
  `[lock+2]` bit 15 the lock bit (`WSZBO 2,1` with ac1=32 resolves to
  `lock + (32>>4)`, mask `0x8000>>(32&0xF)`); `[lock+3]` contender
  count, incremented by `XNISZ` and restored by `XNDSZ`. I.UNLOCK's
  `WMESS` tests the WIDE at `lock+2` against `0x0000FFFF` — the low
  half, i.e. the count — and clears both words atomically.
- **New convention: `WSAVR` rather than `WSAVS`.** No bridge change was
  needed — the pushed image is identical (ac0, ac1, ac2, wfp,
  ac3|carry; no psr), `ovk` is psr bit 15, and `native_return` restores
  psr from the LCALL frame word, so the distinction is invisible after
  return.
- **Dead branches handled by entry-detection + emulation fallback**,
  not by aborting: I.LOCK contended iff `[lock+2]` bit 15 set;
  I.UNLOCK has waiters iff `[lock+3] != 0`. Both are testable before
  any side effect, so the fallback is symmetric (both engines emulate).
- Validation: lockstep session, 3 native pairs, **footprint diff 0
  differing words** over 110 words per pair, zero divergences, clean
  shutdown. Lock object confirmed: `0000 0000 0000 0000` ->
  `0000 0000 8000 0000` across a native acquire.
- **Tooling:** `debug/Capture` gained `QUEST_CAPTURE_DEST=<hex>` — a
  fixed second window. I.LOCK is the first routine whose footprint sits
  at a static address (the lock object at 0x70000200) rather than at a
  caller-supplied one.

Related emulator change: the blocking branch of `REC` (0525) now throws
instead of polling forever, so heap-lock contention fails loudly and
symmetrically. Rationale and the full gap catalogue:
**docs/UNIMPLEMENTED.md**.
